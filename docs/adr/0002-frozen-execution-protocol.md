# 两个执行策略、三个后台阶段是冻结面

状态：已接受

执行协议只有两种形状：主线程操作实现一个 `execute_main`；后台操作实现 `prepare_main` / `execute_worker` / `finalize_main`。这三段的边界就是线程边界——前两段之外都碰不到 QGIS。

理由：每个阶段回答的是"这段代码在哪个线程跑、拿得到什么"。加一个钩子就多一个需要重新回答这个问题的地方，而答案不会是局部答案：它同时改变校验时机、状态迁移、取消语义和 epoch 比对。冻结之后，后台操作想附加能力（例如"图层被删就取消任务"）通过适配器的可选约定表达，不进协议。

被拒的选项：

- **加 `before_finalize` / `on_progress` 之类的钩子**：每个操作都能改写状态机的中间态，"记录只有仓库能写"这条随之失效。
- **让后台操作也能实现 `execute_main`（作为快路径）**：注册时会同时具备两种策略，线程归属变成运行期才知道。

后果：新需求先改设计（写一篇 ADR、改契约、改守卫），不接受以"顺手加个钩子"的方式绕过。
