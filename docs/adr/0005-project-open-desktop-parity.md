# `project.open` 与桌面版同判据：只挡住会让进程死掉的形状

状态：已接受，取代 `0004-project-open-readiness-scan.md`

`project.open` 不再在交给 QGIS 之前做"卫生扫描"。用户能在桌面版打开的工程，`project.open` 也
打开；桌面版不问的东西，它不问。只保留两处实测会让进程直接死掉的检查：

| 保留的检查 | 证据（本机 QGIS 3.44.13） |
| --- | --- |
| 嵌套超过 4096 层拒 | 5500 层 0.10 s 读完，6000 层立刻以 `0xC00000FD` 结束进程 |
| `.qgz` 里有加密成员拒 | `QgsZipUtils::unzip` 会解包每个成员；一个 flag `0x1` 的兄弟成员以 `0xC0000005` 结束进程，连异常都没有 |

不再检查（此前 0004 要求、现在按桌面版放弃）：远程数据源、XML 实体声明、标签数、文件字节数、
解压后字节预算、成员数、非 UTF-8、后缀白名单。逐条都在本机复现过桌面版能做成，且不会让进程死。

理由：`project.open` 是"用户在文件菜单里打开一个工程"的等价物，不是无人值守的自动化 API。桌面版
打开一个 20 MB 的工程、一个带 `WMS` 图层的工程、一个带内联实体的工程都能做成；插件此前把这些
变成错误码，是把一个本来能完成的动作变成失败。判据应当来自那个动作，而不是来自"如果被滥用会怎样"。

被拒的选项：

- **保留整套读前扫描**（0004 的状态）：桌面版能开的文件被拒，调用方拿不到结果，只能绕过插件。
  "慢"不是拒绝的理由：64 MiB 的工程实测 1.8 s 读完。
- **只按文件大小拦**：嵌套 6000 层的工程可以很小，字节数拦不住它。
- **读完之后再检查**：那时进程已经死了，检查只来得及写日志。

代价，调用方要自己知道：

- 一个点着不响应主机的工程，会在主线程上停到网络超时（桌面版同）。这不是插件新增的行为。
- 打开 64 MiB 级别的工程有秒级停顿；`project.open` 跑在主线程，界面在此期间不响应。

## 与 `discard_current` 的关系

替换当前工程仍然要问桌面版问的那四件事：未保存改动、图层的未提交编辑、内存图层的内容、
栅格属性表的改动。四者之一成立且没有 `discard_current=true` 时拒
（`PROJECT_REPLACE_REQUIRED`），因为桌面版在这里会弹框，而 operation 用参数表示同一问句（P2）。
"有关联文件""有图层"不再是问句——桌面版不问它们。
