# 工程文件在读取之前按字节审一遍

状态：已接受

`project.open` 在交给 QGIS 读取之前，用标准库 expat 事件扫描整个文件的文本与属性值，把会让主线程发出网络往返、或让内存失去上限的形状挡在外面：远程字形、XML 实体、非 UTF-8、解压后超预算、成员过多、嵌套过深、标签过多。

理由：读取会就地构造文件里点名的每个图层、取布局里的图片。一个远程 URI 就是主线程上的一次 HTTP 请求或一次带 Windows 凭据的 SMB 连接，等逐层检查时请求已经发出去了——实测 5 KB 的工程让打开动作发出 9 次 TCP，对端接受连接却不回应时主线程停 180.1 秒，最后仍报成功。所以这道检查必须发生在读取之前，而且必须按字节老老实实扫，不能只看元素的首层文本。逐条的实测数字与阈值标定见 `docs/agents/DEVELOP.md` §7.2。

被拒的选项：

- **读完再逐层检查**：请求已经发出去了，检查只来得及记录损害。
- **信任 zip 清单声明的尺寸**：声明 100 字节的档案实测解压峰值 437 MiB。
- **白名单或沙箱**：与 ADR-0001 的决定冲突。

后果：值本身就是 URL 的元数据（`identifier`、option 的 value）会被拒，这类工程打不开——是统一判据的已知代价。这道检查只审调用方点名的文件，不审容器格式内部引用的远程源；把它当访问控制使用会失望，它挡的是主线程上的一次网络往返。
